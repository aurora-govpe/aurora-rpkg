# CLAUDE.md — operating instructions for the aurora package

You are continuing development of **aurora**, an R package that lets people build
*stateless* web apps on top of **plumber2**: author the UI with `bslib`, compile
it to a static `index.html` at build time, and let plumber2 serve those assets
plus JSON API routes. The goal is "Shiny ergonomics, API deployment model".

**Before doing anything, read `dev/STATE.md`** (the resume point), then
`dev/ARCHITECTURE.md` (the canonical app layout) and `dev/PLAN.md` (the phase).

## Canonical app layout (what aurora scaffolds AND reads)

This mirrors the team's real apps (e.g. `app_aurora_novo`). It is fixed by
**convention** — there is no required manifest.

```
<app>/
├── api.R            # entry point; thin, calls aurora::aurora_run(".")
├── build_ui.R       # defines build_ui() -> htmltools tag (sources ui_modules/)
├── helpers/         # *.R sourced BEFORE routers are parsed (utils, db, theme...)
├── routers/         # plumber2 annotated route files (auth.R, ...)
├── ui_modules/      # ui_*.R partials sourced by build_ui.R
├── www/
│   ├── js/core.js   # aurora runtime (basics: fetch, auth) — shipped/updated by aurora
│   ├── js/app.js    # orchestrator — app-authored
│   ├── style.css
│   └── images/
├── data/config.yml  # config (config package)
├── _brand.yml       # optional: visual brand (color/type/logo), consumed by bslib
├── .dockerignore
└── Dockerfile       # generated by aurora_dockerfile()
```

`_aurora.yml` is **optional** and only *overrides* a few keys (`name`, `engine`,
`auth`). If absent, name defaults to the dir name and everything else is
convention. Do not reintroduce a required manifest (see ADR-007).

## Non-negotiable design invariants

Decided deliberately (see `dev/DECISIONS.md`). To change one, write a new ADR.

1. **plumber2 only.** No plumber v1 path. Use `api()`, `api_parse()`,
   `api_assets()`/`api_statics()`, `api_run()`, `api_auth_guard()`.
2. **Thin JS runtime.** `inst/runtime/core.js` stays minimal (a credentialed
   `fetch` wrapper exposing `window.aurora`, + `onUnauthorized`). Rendering and
   orchestration live in the app's `www/js/app.js` and feature JS, not in aurora.
3. **Pluggable auth.** Never in `aurora_app()`'s core path. `aurora_auth_jwt()`
   is one optional scheme meant to wrap plumber2's native guards.
4. **Path comes from the annotation.** A handler's URL is its `#* @get /...`
   value. `aurora_add_route()` embeds the `mount` at scaffold time;
   `aurora_app()` does NO runtime path injection.
5. **UI is static.** `aurora_build_ui()` sources `build_ui.R`, calls
   `build_ui()`, writes HTML via `htmltools::save_html()`. No reactive server.
6. **Convention over manifest.** `aurora_app()` assembles from the fixed layout
   above (parse all `routers/*.R`, source all `helpers/*.R`, serve `www/`).
7. **Theming via brand.yml.** Theming is a `_brand.yml` file consumed natively by
   bslib (`bs_theme(version = 5, brand = TRUE)`), resolved at build time. aurora
   only recognises the file by convention and never builds a theming layer.
   `_brand.yml` is orthogonal to `_aurora.yml` (visual identity vs app wiring);
   do NOT add a `brand` key to `_aurora.yml` (see ADR-011).

## Conventions (match the existing code exactly)

- **Naming:** exported functions are `snake_case` with the `aurora_` prefix.
  Internal helpers are `snake_case`, unexported, no prefix.
- **Logging:** everything user-facing through `cli` (`cli_alert_*`, `cli_abort`,
  `cli_warn`) with inline markup (`{.path }`, `{.fn }`, `{.val }`, `{.url }`).
  No `message`/`warning`/`stop`/`print`/`cat` in new code.
- **Style:** tidyverse; native pipe `|>`; `fs` for all path/file ops; the
  internal `%||%` (in `R/aurora-package.R`).
- **Docs:** every exported function gets a complete roxygen block (`@param`,
  `@return`, `@export`) + a test or an `inst/examples/` app. Roxygen markdown on.
- **Errors:** validate early with `cli_abort()` and an actionable `i =` hint.

## Repo map

- `R/app-config.R` — convention + optional manifest (`read_config`, `router_files`,
  `helper_files`, `assert_is_app`, `resolve_otel`). The layout contract lives here.
- `R/app.R` — `aurora_app()`: convention → plumber2 `api()`. The heart.
- `R/build-ui.R` — `aurora_build_ui()` (runs `build_ui()` with cwd = app dir so
  bslib finds `_brand.yml`). `R/run.R` — `aurora_run()` (+ `watch`, `otel`).
- `R/create-app.R`, `R/add-route.R`, `R/dockerfile.R`, `R/build-image.R`,
  `R/shinyproxy.R` (`aurora_shinyproxy_yaml()`).
- `R/auth.R` — JWT-cookie scheme, WIRED: `aurora_auth_jwt()` + `aurora_jwt_token/
  decode/guard`, `aurora_set/clear_auth_cookie` (jose + reqres; ADR-010).
- `R/component.R` — `aurora_component()` (thin UI↔API helper; ADR-009).
- `R/data-store.R` — `aurora_data_store()` + `_register/_get/_names` (hot-reload).
- `R/watch.R` — live-reload internals for `aurora_run(watch = TRUE)`.
- `inst/runtime/core.js` — the shipped runtime (keep thin; copied to www/js/core.js).
- `inst/templates/{minimal,auth}/` — scaffolding templates (canonical layout).
- `inst/examples/{01-hello,02-dashboard-echarts,03-map}/` — runnable worked apps.
- `tests/testthat/` — tests. New exported function ⇒ new tests.
- `vignettes/` (aurora, migrating-from-shiny, auth, telemetry, deploy +
  `articles/gallery`), `_pkgdown.yml` — the site (builds clean).
- `dev/` — **project memory** (Rbuildignored): STATE, PLAN, ARCHITECTURE,
  DECISIONS, LESSONS, PLUMBER2-NOTES, MIGRATION-V1-V2, BACKLOG. Update as you work.

## Development workflow

```r
devtools::load_all()
devtools::document()    # after any roxygen change — regenerates man/ + NAMESPACE
devtools::test()
devtools::check()       # before declaring a phase done
```

If no R interpreter is available, keep code correct and run a syntax/balance
sanity check; never claim tests passed if you did not run them.

## Definition of done (per task)

1. Code follows the conventions above.
2. `devtools::document()` run (NAMESPACE/man updated).
3. Tests added/updated and passing (or written + explained if R unavailable).
4. `dev/STATE.md` updated.
5. New design choice ⇒ append an ADR to `dev/DECISIONS.md`.
6. New gotcha ⇒ append to `dev/LESSONS.md`.

## Known gotchas (full list in dev/LESSONS.md)

- **Query params do NOT bind to named handler args** in plumber2 — only path
  `<var>` do. Read query via the `query` arg, body via `body`; `req`/`res` are
  reqres `request`/`response`. (Full v1→v2 map: `dev/MIGRATION-V1-V2.md`.)
- A `@header`/`@any /api/*` guard must return `plumber2::Next` — **namespaced**,
  because plumber2 isn't attached during aurora's assembly (bare `Next` → 500).
- reqres `set_cookie(same_site=)` wants `"Lax"`/`"Strict"`/`"None"` (capitalised);
  cookies live outside `$headers` until serialised (use `res$as_list()` in tests).
- `\uXXXX` escapes work in R **string literals** but NOT in roxygen `#'` text —
  they leak into `.Rd` as an unknown `\u` macro (WARNING). Use ASCII in roxygen.
- `bs_theme(brand = TRUE)` needs the `brand.yml` pkg and discovers `_brand.yml`
  relative to cwd; `aurora_build_ui()` sets cwd to the app dir for the build.
- `htmltools::HTML()` takes ONE string — `paste(..., sep="\n")` first.
- No `\\`+newline continuation inside `cli` strings (renders a literal `\`).
- `fs::dir_copy(src, dst)` nests under `dst` if it pre-exists; delete `dst` first.
  `fs::path(".", "/abs")` does NOT collapse — use `fs::path_abs(p, start=dir)`.
- Helpers are `sys.source()`d into the global env so router handlers can see
  them; prefer that over `<<-`/globals inside helpers.
- plumber2 default port is 8080, docs at `/__docs__`; aurora defaults to 8000.
- Test routes without a server: `pa$test_request(fiery::fake_request(...))`
  (`content` must be a character string, default `""`).

## What NOT to do

- Don't add plumber (v1) anywhere.
- Don't grow `core.js`/`app.js` handling into a rendering framework in the pkg.
- Don't bake auth into `aurora_app()`'s core path.
- Don't inject URL prefixes at runtime in `aurora_app()`.
- Don't reintroduce a required manifest; convention is the source of truth.
- Don't introduce heavy dependencies without an ADR.
